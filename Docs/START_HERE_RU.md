# Запуск и сдача COINBOUND

## Сначала открыть проект

1. Распакуй архив в НОВУЮ папку. Старый проект сохрани отдельно.
2. Unity Hub -> Add -> Add project from disk. Выбери папку, где рядом лежат Assets, Packages, ProjectSettings.
3. Открывай через Unity 6.6. В архиве указан ориентир 6000.6.2f1; точная версия исходного проекта не была прислана. Unity 2022 не подходит к использованному API Rigidbody2D.linearVelocity.
4. Дождись загрузки пакетов. Если Unity предлагает включить Input System и перезапуститься, согласись.
5. Меню Tools -> Mobile Game -> 1. Prepare Project and Bake UI.
6. Открой Assets/mainmenu.unity и нажми Play.

Название COINBOUND выбрано для проекта и GDD. Оно меняется в MobileGameUI.GameTitle; после изменения снова запусти Prepare Project and Bake UI и обнови GDD.

Старые Canvas сохранены выключенными. Новый интерфейс расположен в MobileGameUI/MobileCanvas. Он создаётся скриптом при запуске; команда Bake делает его также видимым в редакторе. Постоянные изменения расположения делай в MobileGameUI.cs и повторяй Bake. Изменение только сгенерированных объектов будет сброшено при загрузке сцены.

## Телефон Android

1. В Unity Hub у своей версии Unity открой Add modules.
2. Установи Android Build Support, Android SDK & NDK Tools, OpenJDK.
3. В проекте File -> Build Profiles -> Android -> Switch Platform; дождись импорта.
4. Tools -> Mobile Game -> 2. Build Android APK.
5. Готовый файл после успешной сборки: Builds/Android/Coinbound.apk.
6. Перенеси APK на телефон и установи. Это Android APK, на iPhone он не устанавливается.
7. Проверь движение одним пальцем и прыжок/стрельбу другим. Удержание FIRE повторяет выстрелы.
8. Проверь Pause, Resume, Restart, Main Menu; сверни игру и вернись: должна открыться пауза.

Здесь Unity и Android SDK не установлены. APK в архиве нет; компиляция, реальное нажатие пальцами и работа на устройстве пока НЕ подтверждены. Если появится ошибка, пришли первую красную ошибку Console полностью, версию Unity и модель/ОС телефона.

## Проверка интерфейса

Открой Device Simulator (путь из лекции: Window -> General -> Device Simulator).
Проверь 16:9, телефон с вырезом 19.5:9/20:9, планшет 4:3. Проверь меню, HUD, паузу на каждом устройстве.
Canvas настроен на 1920x1080, Match 1; текст и кнопки внутри SafeArea, фон снаружи.
Обычные кнопки не меньше 120 по каждой оси, JUMP/FIRE 220x220, джойстик 320x320; текст от 36.

- Ссылку на доступный преподавателю GitHub в комментарий.
- HUD: скриншоты на 16:9, телефоне с вырезом и планшете.
- Главное меню и паузу: ещё два скриншота.
- MP4 2-3 минуты с твоим голосом на английском. Используй VIDEO_SCRIPT_EN.md как план, рассказывай только то, что реально проверил.

Команда Tools -> Mobile Game -> 3. Capture Screenshot (Play Mode) сохраняет кадр в Submission/Screenshots. Открой и проверь каждый снимок: он должен показывать нужный экран и размер, без панелей редактора поверх игры. Если снимок из симулятора получился некорректным, сделай обычный снимок окна Device Simulator.

Видео и скриншоты не подделаны и в этой среде не записаны: их нужно получить из настоящего запуска Unity. Финальные файлы загрузи в Canvas сам.
